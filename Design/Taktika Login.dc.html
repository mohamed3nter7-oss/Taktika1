Log in

Two compositions of the same form: a centred card on the base surface, and a split layout with a brand panel. The form itself is identical in both — email, password, one primary action, two links. Nothing else appears, because every control on this screen is a promise the backend has to keep.

"Log in", not "Sign in"

Verb first, already minimal, and its counterpart is "Create account" rather than "Sign up" — sign in and sign up differ by one letter, which is a scanning hazard in a bilingual product where neither word is the user's first language. The pair carries through to log out.

What the floodlight gave us

One light source, one lit area, everything else near black. Expressed with the means the system already has: a raised surface on the base surface is a lightness step, so the card reads as the lit object and the rest of the viewport stays empty. No gradient, no glow, no photograph — the whole effect is one surface token and a lot of restraint.

Two failures, two treatments

Wrong credentials is recoverable by retyping, so it is an inline danger-tint notice above the fields and the form stays intact. Suspension is not recoverable by retyping, so it replaces the form entirely, steps up to the overlay surface, and uses warning rather than danger — the account is not wrong, it is unavailable, and it carries a date.

Not designed, deliberately

No OAuth row, no remember me, no OTP, no unverified-account error. There is also no error state for a first-time visitor: the only route off this screen is create account, and it sits below the divider where it stays available without competing with the primary action.

Three things to decide

Password reveal is missing, and I did not invent it. Input has an iconStart slot and no trailing slot, so a reveal toggle cannot be composed without either a new primitive or an absolutely positioned IconButton laid over a component's internals. Add a trailing action slot to Input, or ship without reveal. Designed here without it.

The language toggle is my addition. This is the first screen a user meets and the product is EN/AR, so switching has to be possible before authenticating. It is a ghost Button, not navigation. Cut it if locale is resolved server-side from the account or the browser.

No icons are used on this screen. Not a rule, just an outcome: the notice is carried by danger tint and danger text, and suspension by a warning Badge and the overlay surface, so an Icon would have been decoration. Lucide is also unreachable from this preview, which is why you will not see one anywhere here.

The form-level notice is Card-shaped but is not a Card. It is a div on danger-tint with an Icon. If it recurs on register or password reset, it wants a name — Notice or Alert — as a real addition to the set rather than three near-identical improvisations.

Recommendation

Ship 1a, the centred card

A brand panel has to be filled with something, and the only honest content for a returning user is a positioning line they have already accepted by signing up. The system also forbids the imagery that makes split layouts work, so B's panel is a large flat rectangle of type — weaker than empty base surface, and a second layout to maintain because it collapses to A below 1024 anyway. The centred card is one composition across 1280, 768 and 390, it mirrors for Arabic by inheriting direction rather than by overriding anything, and it puts the only primary action at the optical centre of the screen. It is also the honest reading of the floodlight reference: one lit object, everything else dark, achieved with a single surface step instead of a photograph. Build B only if login has to carry acquisition traffic, and then it needs real imagery and a rule change first.
